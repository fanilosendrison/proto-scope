## Problem

Four current Ruu artifacts declare the date 2026-11-03 in material associated with ADR-081 / post-baseline qualification:

```text
qualification/state-space/post-baseline/v046/state-space-audit-v46.md
qualification/audits/hostile/hostile-audit-adr081.md
qualification/package-verification/package-verification-adr081.md
docs/design/decision-integration-log.md
```

ADR-081 itself declares:

```text
date: 2026-09-10
```

The anomalous artifacts were introduced in repository history before 2026-11-03.

Current Ruu checks authenticate bytes, manifests, registration, replay, lineage, and exact evidence bindings, but do not establish the semantic truth/currentness of these date assertions.

A structurally valid/hash-bound/replayable artifact is therefore currently capable of carrying an ungoverned provenance assertion.

## Critical distinction

Do NOT treat the four occurrences as one semantic fact merely because the literal date is the same.

They currently expose at least two distinct cases.

### A. Decision Integration Log

docs/design/decision-integration-log.md contains:

```text
## 2026-11-03 — ADR-081 — ...
```

Determine whether this heading date is intended to represent canonical ADR-081 decision metadata.

If it is a secondary representation of ADR metadata, confront it against the canonical ADR-081 authority and the existing Projection Integrity rules.

Do not infer correctness from Git commit timestamps.

### B. Qualification / audit artifacts

The following artifacts each contain a Date assertion:

```text
qualification/state-space/post-baseline/v046/state-space-audit-v46.md
qualification/audits/hostile/hostile-audit-adr081.md
qualification/package-verification/package-verification-adr081.md
```

The current post-baseline qualification-metadata.json registration records version, provenance class, baseline, artifact hashes, supporting artifacts, and replay contract, but it does not currently declare a canonical timestamp/date authority for these report fields.

For each occurrence, first determine exactly what the field claims to mean.

Do not assume that the ADR date, Git author date, Git committer date, file introduction date, execution date, report generation date, or any other wall clock is interchangeable.

## Authority rule

Ruu owns the consumer-specific semantics and adjudication.

For every anomalous occurrence determine:

```text
claimed fact
authoritative source, if one exists
admissible binding from source to representation
current status:
    ESTABLISHED
    MISMATCH
    UNKNOWN / UNDETERMINED
```

If no currently accepted Ruu authority establishes the claimed date, record the value as unknown/undetermined rather than manufacturing a replacement.

In particular:

```text
2026-09-10 MUST NOT be substituted merely because ADR-081 has that date.
Git author/committer timestamps MUST NOT be promoted into semantic authority merely because they exist.
independent wall clocks MUST NOT be treated as causal proof.
```

## Historical preservation / correction boundary

Do not silently rewrite accepted or historical evidence in place.

Preserve the anomalous artifacts and their provenance sufficiently for the repository history to show what was previously claimed.

Follow current Ruu qualification policy: a correction to accepted qualification should normally be represented by the next version.

Where an erratum, corrective qualification, maintained projection correction, or another explicit correction form is required, use the form authorized by current Ruu governance.

Do not falsify v46 history to make the old artifact look as though it always carried the corrected provenance.
